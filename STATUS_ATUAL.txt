================================================================================
# FITMANAGER SAAS - STATUS DE CONTEXTO (ATUALIZADO)
================================================================================

Resumo técnico para continuidade do FitManager após decisão de migração de
Supabase para Firebase.

--------------------------------------------------------------------------------
1. STACK E ARQUITETURA (ESTADO ATUAL)
--------------------------------------------------------------------------------
- Frontend: Next.js (App Router), Tailwind CSS v4, Shadcn UI.
- Backend: Node.js (Express) com TypeScript (ts-node no dev).
- Banco e Auth (decisão de produto): Firebase.
- Repositório: git@github.com:smateusx/FitManager.git.

--------------------------------------------------------------------------------
2. SITUAÇÃO DA MIGRAÇÃO
--------------------------------------------------------------------------------
- A base funcional da aplicação ainda contém chamadas de Supabase no frontend.
- O backend não depende mais do SDK do Supabase (dependência removida).
- Foi adicionada uma base de cliente Firebase em `frontend/src/lib/firebase.ts`.
- Existe um plano técnico em `MIGRATION_SUPABASE_TO_FIREBASE.md`.

--------------------------------------------------------------------------------
3. O QUE CONTINUA VÁLIDO NO PRODUTO
--------------------------------------------------------------------------------
- Fluxos de negócio já desenhados:
  - Autenticação por papel (ADMIN, RECEPCIONISTA, ALUNO)
  - Gestão de alunos, treinos, planos, matrículas e cobranças
  - Portal do aluno e recursos de evolução
  - Relatórios PDF/Excel no dashboard
- Integração de WhatsApp segue independente de provedor de banco/auth.

--------------------------------------------------------------------------------
4. PRÓXIMOS PASSOS PRIORITÁRIOS
--------------------------------------------------------------------------------
1. Migrar autenticação (`use-auth`, login, registro) para Firebase Auth.
2. Migrar camada de dados das páginas admin/aluno para Firestore.
3. Migrar upload de avatar para Firebase Storage.
4. Converter scripts SQL legados para documentação de coleções/regras Firebase.
5. Revisar lint/typecheck após migração dos módulos críticos.

--------------------------------------------------------------------------------
5. COMO RODAR (ATÉ CONCLUSÃO DA MIGRAÇÃO)
--------------------------------------------------------------------------------
- Frontend:
  1) `cd frontend`
  2) `cp .env.example .env.local`
  3) preencher variáveis `NEXT_PUBLIC_FIREBASE_*`
  4) `npm run dev`
- Backend:
  - `cd backend && npx ts-node src/server.ts`
