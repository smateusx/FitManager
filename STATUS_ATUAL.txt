# FITMANAGER SAAS - DOCUMENTO DE CONTEXTO E TRANSFERÊNCIA
================================================================================

Este documento resume o estado atual do desenvolvimento do FitManager, um SaaS
brasileiro para gestão de academias, para que outra IA possa retomar o trabalho
com total clareza técnica e de produto.

--------------------------------------------------------------------------------
1. TECH STACK & ARQUITETURA
--------------------------------------------------------------------------------
- Frontend: Next.js (App Router), Tailwind CSS (v4), Lucid React (ícones), Shadcn UI.
- Backend: Node.js (Express) com TypeScript (rodando atualmente via ts-node).
- Banco de Dados & Auth: Supabase (PostgreSQL + RLS).
- Repositório Git: git@github.com:smateusx/FitManager.git (Branch: main).

--------------------------------------------------------------------------------
2. O QUE JÁ FOI IMPLEMENTADO (STATUS: FUNCIONAL)
--------------------------------------------------------------------------------
- AUTENTICAÇÃO:
    - Login e Registro de Academia (Admin).
    - Redirecionamento inteligente por papel (Role): 
        - Admin/Recepcionista -> /dashboard
        - Aluno -> /meu-treino
    - Correção de bugs de confirmação de e-mail e RLS recursiva.

- PLANOS & PAGAMENTOS:
    - Cadastro de planos (nome, valor, duração).

- EVOLUÇÃO DE CARGA (Aluno):

- EDITOR DE PERFIL:
    - Página de configurações para Admin (/perfil) e Aluno (/meu-perfil).
    - Upload de foto de perfil integrado ao Supabase Storage.
    - Alteração de nome, telefone e senha.

--------------------------------------------------------------------------------
3. CONFIGURAÇÕES CRÍTICAS DO SUPABASE (IMPORTANTE)
--------------------------------------------------------------------------------
- TABELAS: academias, perfis, fichas_treino, exercicios, planos, matriculas.
- TRIGGER EM auth.users: Ao criar usuário, insere automaticamente em public.perfis.
    - O trigger lê 'nome_completo' e 'academia_id' do metadata do auth.signUp.
- RLS (Row Level Security): Rigorosamente aplicado. O administrador só vê dados de sua academia. O aluno só vê seus próprios treinos e matrículas.
- FIX RECURSÃO: Foi criada uma função `public.get_my_academia_id()` para evitar loops infinitos nas políticas de segurança da tabela 'perfis'.
